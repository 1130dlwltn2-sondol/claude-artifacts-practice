# 4장. 자료를 넣고 구조화하기

학습목표: 원본 데이터와 AI의 추론을 분리하고, 수치를 직접 검산한다.

## 개념

문서에 숫자가 들어가면 프롬프트 기술이 한 단계 더 필요합니다. Claude는 계산을 잘하는 것처럼 보이지만, 가끔 합계나 평균을 틀립니다. 더 흔한 문제는 원본 데이터에 없는 것을 추론해서 사실처럼 적는 것입니다. "주문량이 늘었다"는 원본에 있는 사실이지만, "마케팅 효과로 늘었다"는 AI의 추론입니다. 이 둘을 분리하지 않으면 보고서가 소설이 됩니다.

원칙은 단순합니다. 원본 데이터만 쓰게 하고, 계산식을 쓰게 하고, 모르는 것은 가정 목록으로 받습니다. "첨부한 가상 데이터만 사용해"라고 하면 외부 지식을 끌어오지 않습니다. "각 수치의 계산식을 쓰고"라고 하면 426건이 어떻게 나왔는지 추적할 수 있습니다. "불명확하면 질문 대신 가정 목록을 제시해줘"라고 하면 Claude가 멈추지 않고, 대신 무엇을 가정했는지 밝힙니다. 가정은 나중에 검증하면 됩니다. 숨은 추론은 검증할 수 없습니다.

파일 첨부도 알아둡시다. CSV 같은 표 파일을 대화에 첨부하면 Claude가 읽고 분석합니다. 파일 첨부 경험이 선수지식으로 적힌 이유입니다. 첨부할 때는 개인정보가 없는 가상 데이터를 쓰세요. 실데이터는 6장에서 다루는 주의사항을 익힌 뒤에 다룹니다.

이 장에서 쓰는 가상 CSV는 이 책 전체의 기준 데이터입니다. 6장의 대시보드 명세서에서도 같은 데이터를 씁니다. 여기서 합계와 평균을 직접 검산해 두면, 뒤의 장에서 숫자가 틀렸는지 바로 알 수 있습니다.

## 언제 쓰는가

- 표 데이터를 요약 보고서로 바꿀 때
- 합계·평균 같은 지표를 계산해야 할 때
- 데이터에 결측값이나 이상값이 있을 때

## 사전 준비

- 아래 가상 CSV 데이터 (모든 수치는 가상입니다. 직접 검산해 보세요)
- 계산기 (손검산용)

가상 CSV (가상 서점 책마루 2026년 9월 일별 주문, 가상):

## 단계별 실습

1. 위 CSV를 복사해 Claude 대화에 붙여넣거나 파일로 첨부합니다.
2. 프롬프트 1을 입력해 항목별 합계·평균·결측값을 분석해 달라고 합니다.
3. 결과물의 합계(주문 426건, 매출 12,780,000원)를 계산기로 직접 검산합니다.
4. 평균(주문 42.6건, 매출 1,278,000원, 평균객단가 30,000원)을 검산합니다.
5. 계산식이 적혀 있는지, 가정이 목록으로 제시됐는지 확인합니다. 틀린 수치는 프롬프트 2로 수정을 요청합니다.

## 복사해서 쓰는 프롬프트

프롬프트 1 (데이터 분석):

첨부한 가상 데이터만 사용해 항목별 합계·평균·결측값을 분석해줘. 각 수치의 계산식을 쓰고 불명확하면 질문 대신 가정 목록을 제시해줘.

프롬프트 2 (수치 수정 요청):

주문 합계가 틀렸어. 38+41+35+44+52+48+39+43+46+40=426이야. 이 계산식으로 다시 계산해줘.

## 입력 예시

입력: 위 가상 CSV 10행
출력 기대: 합계·평균·결측값 표, 각 수치의 계산식, 가정 목록

## 성공 예시

결과물에 "주문 합계 426건 = 38+41+35+44+52+48+39+43+46+40"이라고 계산식이 적혀 있습니다. 결측값은 "없음"으로, 가정은 "매출액은 주문건수에 단가를 곱한 것으로 가정"처럼 목록으로 제시됐습니다. 손검산 결과와 일치합니다.

## 실패 예시

"주문 합계 약 430건"이라고 어림값이 적혀 있습니다. 계산식이 없고, "주말 효과가 보인다"는 추론이 사실처럼 적혀 있습니다. 이런 결과물은 보고서에 쓸 수 없습니다. 계산식을 요구하지 않으면 이런 결과가 나옵니다.

## 오류 해결

- 합계가 틀림: 계산식을 쓰게 하고 직접 검산하세요. 틀리면 프롬프트 2처럼 올바른 계산식을 직접 제시하세요.
- 결측값을 0으로 처리함: "결측값은 0이 아니라 결측으로 표시해"라고 명시하세요.
- 원본에 없는 해석이 섞임: "해석하지 말고 수치만 정리해줘"라고 하거나, 해석과 사실을 분리해 달라고 요청하세요.

- [ ] 각 수치의 계산식이 결과물에 있는가?
- [ ] 가정이 목록으로 제시됐는가?

## 확인 문제

1. "각 수치의 계산식을 쓰고"라고 프롬프트에 넣는 이유는?
   가. 문서가 길어져서 좋아 보여서
   나. 수치의 출처를 추적하고 검산할 수 있게 하기 위해
   다. Claude가 표를 예쁘게 만들어서
   라. 가정 목록을 없애기 위해
   정답: 나. 계산식이 있어야 틀린 수치를 찾고 고칠 수 있습니다.

2. "불명확하면 질문 대신 가정 목록을 제시해줘"의 효과는?
   가. Claude가 멈추지 않고, 무엇을 가정했는지 밝히게 한다
   나. 질문이 아예 안 나온다
   다. 계산이 빨라진다
   라. 결측값이 사라진다
   정답: 가. 가정은 나중에 검증하면 되지만, 숨은 추론은 검증할 수 없습니다.

## 자주 묻는 질문

Q. CSV 파일 첨부와 복사·붙여넣기 중 뭐가 나은가요?
A. 행이 많으면 파일 첨부가 낫습니다. 복사·붙여넣기는 길면 잘리거나 형식이 깨질 수 있습니다. 10행 정도는 둘 다 됩니다.

Q. 실데이터를 써도 되나요?
A. 아직은 안 됩니다. 이 책의 실습은 모두 가상 데이터로 합니다. 실데이터는 6장의 개인정보·권한 주의사항을 읽고 조직 정책을 확인한 뒤에 쓰세요.

## 출처 확인

- 가상 CSV의 합계·평균은 저자가 직접 검산했습니다 (426건, 12,780,000원, 평균객단가 30,000원)
- Claude 공식 도움말의 파일 분석 안내는 공식 도움말에서 확인하세요 (확인일 2026-10-10)
- 예제 데이터와 수치는 모두 가상입니다
